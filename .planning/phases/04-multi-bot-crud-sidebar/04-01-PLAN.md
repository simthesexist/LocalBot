# Plan 04-01 — Tracer slice: bot metadata CRUD + per-bot policy + BotSidebar + modals

**As a** Localbot user,
**I want to** see the implicit `default` bot in a left-rail sidebar, create a new bot through a modal, and delete a bot through a typed-name confirmation,
**so that** the Phase 4 architecture (daemon JSON-RPC for bot metadata + per-bot allowlist + main IPC bridge + renderer sidebar + modal stack) is proven end-to-end on one vertical slice before the rest of the surface (update / trigger / cancel / settings / run history) lands in Waves 2 and 3.

## Objective

Prove the Phase 4 architecture end-to-end with one vertical slice that touches every layer the phase modifies:

- **Daemon side** — `bots/loader.cjs` for atomic `config.json` read/write/delete with schema validation; `bots/policy.cjs` for per-bot allowlist loader that replaces the hardcoded `DEFAULT_POLICY`; new JSON-RPC methods `bots/list`, `bots/create`, `bots/delete` in `main.cjs`; `registry.cjs#getPolicy()` now delegates to `bots/policy.cjs`; audit lines written for every bots/* op.
- **Main side** — `src/main/ipc/bots.ts` registers `BOTS_LIST`, `BOTS_CREATE`, `BOTS_DELETE` IPC handlers; `src/main/daemon/spawn.ts` adds `callBot(method, args)` helper; `src/main/bots/config.ts` wraps the daemon calls with TypeScript types; `src/main/window.ts` extends the `app:init` payload to include the bot list so the renderer's first paint shows the sidebar populated; `src/main/bots/paths.ts` adds `configPath(bot)` and `runsDir()` helpers used in Wave 2; `EVENT_BOT_LIST_UPDATED` broadcasts on every mutation.
- **Renderer side** — `src/renderer/state/bots.ts` exposes `useBots()` and `useActiveBotId()` module-scope stores subscribed to `EVENT_BOT_LIST_UPDATED`; `BotSidebar` renders one `SidebarBotRow` per bot with status dot + name + last-run text; `NewBotModal` collects the AGENT-01 fields; `DeleteConfirmModal` enforces the typed-name AGENT-02 contract; `AppModal` is the shared modal primitive (Escape + backdrop + focus trap); `Chat.tsx` replaces Phase 3's 240 px `WorkspaceTree` left rail with `BotSidebar` at 260 px.
- **Tests** — 3 new Vitest suites (`bot_config`, `bot_crud`, `bot_policy`) cover the Wave 0 unit requirements from `04-VALIDATION.md`.

This is the **tracer** slice. Every layer the phase touches gets exercised end-to-end on the create+list+delete path before Wave 2 layers in `bots/update`, `bots/trigger`, `bots/cancel`, and run history.

## Purpose

Phase 1+2+3 established IPC, JSON-RPC, audit, AbortController, safePath, and per-bot JSONL routing. Phase 4's risk is **bot metadata as a first-class addressable surface**: every tool call needs a per-bot allowlist (SEC-02); every chat turn needs the right bot id (AGENT-01); the renderer needs to discover bots dynamically (UI-01). The hardcoded `default` bot that Phase 3 carries as an implicit singleton must become a discoverable list with explicit `config.json` per bot. This plan proves the per-bot policy loader + the JSON-RPC CRUD surface + the modal stack on one slice before the rest of the UI surface (sidebar actions, settings page, run history) multiplies.

## Output

- Daemon `bots/loader.cjs` + `bots/policy.cjs` + 3 new JSON-RPC methods in `daemon/main.cjs` + per-bot policy delegation in `daemon/tools/registry.cjs`.
- Main `src/main/ipc/bots.ts` + `src/main/bots/config.ts` + `src/main/bots/paths.ts` + `src/main/daemon/spawn.ts#callBot` + `EVENT_BOT_LIST_UPDATED` broadcast hook.
- Renderer `BotSidebar`, `SidebarBotRow`, `NewBotModal`, `DeleteConfirmModal`, `AppModal`, `state/bots.ts`.
- 3 new Vitest unit suites (bot_config, bot_crud, bot_policy) passing.
- `npm run build` exits 0 with the new files compiled to `dist/main` + `dist/renderer`.

<acceptance_criteria>
- `daemon/bots/loader.cjs` exports `readConfig(userDataDir, bot)`, `writeConfig(userDataDir, bot, cfg)`, `listAllBots(userDataDir)`, `deleteBot(userDataDir, bot)`, `deriveSlug(name)`. All functions use `safePath(ctx.botDir, 'config.json')` for containment; `writeConfig` does atomic `tmp + rename` via `fs.writeFileSync(tmp, ...)` then `fs.renameSync(tmp, real)`.
- `readConfig` returns `null` on `ENOENT`; throws `Object.assign(new Error('unknown config key: <k>'), {code: 'invalid_config'})` for any key outside `ALLOWED_CONFIG_KEYS = new Set(['id','name','persona','workspace','allowlist','cron','cronEnabled','createdAt','updatedAt','status','lastRunAt','lastRunExitReason','lastRunError','schemaVersion'])`.
- `writeConfig` validates `cfg.schemaVersion === 1`; sets `cfg.createdAt = cfg.createdAt ?? new Date().toISOString()` and `cfg.updatedAt = new Date().toISOString()`; defaults `status = 'idle'` if absent; rejects `id` that does not match `/^[a-z0-9][a-z0-9-]{0,31}$/`.
- `listAllBots(userDataDir)` scans `<userData>/bots/*/config.json`; returns `BotConfig[]` sorted by `name` ascending; if no bots directory exists, returns `[{id:'default', name:'Default bot', persona:'', workspace:'', allowlist:[], schemaVersion:1, createdAt:<now>, updatedAt:<now>, status:'idle'}]` so the renderer always sees the implicit default bot.
- `deleteBot(userDataDir, bot)` removes `<userData>/bots/<bot>/` via `fs.rmSync(path, {recursive: true, force: true})`; throws `code: 'unknown_bot'` if the dir is missing.
- `deriveSlug(name)` lowercases the name, replaces `[^a-z0-9-]` with `-`, collapses consecutive dashes, trims leading/trailing dashes, truncates to 32 chars; throws `code: 'invalid_id'` if the result is empty.
- `daemon/bots/policy.cjs` exports `getPolicy(botId, ctx)`. It calls `readConfig(ctx.userDataDir, botId)`; if `cfg === null && botId === 'default'`, returns `DEFAULT_POLICY`; if `cfg === null && botId !== 'default'`, throws `Object.assign(new Error('unknown bot: '+botId), {code: 'unknown_bot'})`; else returns `{allowlist: new Set(Array.isArray(cfg.allowlist) ? cfg.allowlist : []), denylist: new Set()}`.
- `daemon/tools/registry.cjs#callTool(botId, name, args, ctx)` is extended: it calls `require('./bots/policy.cjs').getPolicy(botId, ctx)` instead of the hardcoded `DEFAULT_POLICY`. The `_system` bot path keeps the existing SYSTEM_TOOLS short-circuit.
- `daemon/main.cjs` adds three JSON-RPC methods registered in the `switch (method)` block:

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer -> IPC | Untrusted renderer; cannot write bot config files directly; all CRUD goes through preload `window.localbot.bot.*` -> main IPC -> daemon JSON-RPC |
| main -> daemon (JSON-RPC) | Main owns the bot CRUD IPC bridge; daemon enforces `safePath` containment for `<userData>/bots/<bot>/config.json` |
| daemon -> filesystem | Daemon's `bots/loader.cjs` uses `safePath` to enforce `<userData>/bots/<bot>/` containment; rejects `..` traversal and `id` regex mismatch |
| renderer -> LLM | Bot metadata (persona, allowlist) flows into the LLM system prompt via `injectPersonaSuffix` in Wave 2; persona is untrusted data and the system prompt fences it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-P4-01 | Tampering | Bot id path traversal (`config.json` write to `../etc/passwd`) | critical | mitigate | `bots/loader.cjs#writeConfig` enforces `id` regex `/^[a-z0-9][a-z0-9-]{0,31}$/`; `safePath` enforces `<userData>/bots/<id>/` containment; `tests/unit/bot_config.test.ts` proves the rejection |
| T-P4-02 | Tampering | Per-bot allowlist bypass via unknown bot id | high | mitigate | `bots/policy.cjs#getPolicy` throws `code:'unknown_bot'` for any bot without a config.json (except the implicit `default`); registry short-circuits allowlist only for `_system` SYSTEM_TOOLS; `tests/unit/bot_policy.test.ts` covers both paths |
| T-P4-03 | Tampering | Allowlist policy cached across updates | high | mitigate | `getPolicy()` reads `config.json` from disk on every call (no module-scope cache); Phase 4 `bots/update` (Wave 2) is the only writer and audit-logged |
| T-P4-04 | Repudiation | Bot CRUD op audit gaps | medium | mitigate | Every bots/list, bots/create, bots/delete call writes one JSONL line via the existing `audit.appendAudit(...)` (daemon-side) + `appendAuditLine(...)` (main-side mirror); canonical Phase 2/3 shape `{ts, bot, tool, params, outcome, durationMs, error?}` |
| T-P4-05 | Tampering | Delete default bot (Phase 3 backward compat) | high | mitigate | `bots/delete` in `daemon/main.cjs` rejects `params.bot === 'default'` with `code:'protected_bot'` so the implicit bot survives |
| T-P4-06 | Tampering | config.json race during concurrent updates | medium | mitigate | `writeConfig` does atomic `tmp + rename` (Windows Node 14+ guarantees atomic rename); tests verify that a rename failure leaves the original file untouched |
| T-P4-07 | Tampering | Unknown config.json keys bypass schema validation | medium | mitigate | `readConfig` throws `{code:'invalid_config'}` for any key outside `ALLOWED_CONFIG_KEYS`; forward-compatibility: adding a new key requires updating the set (no silent acceptance) |
