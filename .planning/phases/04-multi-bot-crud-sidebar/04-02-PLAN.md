# Plan 04-02 — Trigger / Cancel / Run history / Settings edit / Sidebar composer

**As a** Localbot user,
**I want to** manually trigger any bot from the sidebar composer, watch it stream a response with the right persona injected, edit the bot's persona / workspace / allowlist / cron from a settings modal, and see the bot's status flip to running and back to idle,
**so that** the Phase 4 manual-trigger + settings-edit surface is complete — every layer that the trigger round-trip touches (daemon bots/trigger + bots/cancel + per-bot run-id AbortController + main IPC bridge + renderer SidebarComposer + status subscription) is wired end-to-end.

## Objective

Expand the Wave 1 tracer into the trigger / cancel / settings-edit surface:

1. **Daemon side** — `bots/update` (atomic patch with schema re-validation), `bots/trigger` (runs one sendMessage cycle + writes RunRecord + broadcasts status), `bots/cancel` (aborts per-runId AbortController + writes cancelled RunRecord). `bots/trigger` and `bots/cancel` are separate from `tools/call` because they manage state (run history + status broadcast) — they reuse Phase 1's NDJSON transport but invoke the daemon's own agentic loop.
2. **Main side** — `src/main/runs/jsonl.ts` (NDJSON per-bot mutex + reverse-order reader), `src/main/bots/runs.ts` (typed wrappers), `src/main/bots/policy.ts` (loadConfigIntoSystemPrompt + injectPersonaSuffix), `src/main/ipc/bots.ts` extends with BOTS_UPDATE/BOTS_TRIGGER/BOTS_CANCEL, `src/main/ipc/chat.ts` routes by req.bot, `src/main/llm/prompts.ts` adds DEFAULT_SYSTEM_PROMPT_BASE + injectPersonaSuffix. Per-runId AbortController map lives in `src/main/ipc/bots.ts`.
3. **Renderer side** — `SidebarComposer` (textarea + send), `SettingsEditModal` (form for AGENT-04), extended `BotSidebar` (mounts composer + shows live status), extended `SidebarBotRow` (play/stop/settings actions), extended `state/bots.ts` (subscribes to EVENT_BOT_STATUS).
4. **Tests** — 1 new Vitest suite (bot_runs), 3 extended suites (bot_crud, bot_policy, allowlist).

## Purpose

Wave 1 proved the bot metadata CRUD + sidebar render. Wave 2 closes the live surface: every settings field is editable (AGENT-04); the user can trigger any bot from the sidebar and watch streaming tokens arrive (AGENT-07); cancel mid-run aborts the in-flight cycle (AGENT-08); the bot list reflects live status changes via the new event channel. Without Wave 2, Wave 3's settings page would have no edit surface and the run history table would have no rows to display.

## Output

- `bots/update`, `bots/trigger`, `bots/cancel` JSON-RPC methods in daemon.
- `src/main/runs/jsonl.ts` + `src/main/bots/runs.ts` (NDJSON run history).
- `src/main/ipc/bots.ts` extends with 3 new handlers + per-runId AbortController map.
- `src/main/ipc/chat.ts` routes by `req.bot` and injects persona into every system prompt.
- `SidebarComposer`, `SettingsEditModal`, extended `BotSidebar` + `SidebarBotRow` + `state/bots.ts`.
- 1 new + 3 extended Vitest suites passing.
- `npm run build` exits 0.
