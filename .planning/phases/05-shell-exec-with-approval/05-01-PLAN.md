<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Renderer to Main IPC | Renderer issues shell:respond {shellId, decision}; main proxies it to the daemon's shell/respond JSON-RPC method. Main NEVER decides the approval - it routes the user's decision. |
| Main to Daemon JSON-RPC | Main's spawn.ts proxies shell:respond and tools/call to the daemon over the NDJSON pipe. Daemon is the trust boundary that holds the pending Promise. |
| LLM (Anthropic SDK) to Daemon | The LLM emits a tool_use block with name:exec_command and input.command. The daemon's tools/call dispatch is where the denylist check + allowlist gate + approval round-trip live. The renderer NEVER sees the raw ChildProcess. |
| Daemon child to host OS | spawn(cmd.exe /d /s /c) or spawn(/bin/sh -c) creates a child process tree on the user's machine. killChildTree must traverse the tree (taskkill /T /F or process.kill on the group). |
