## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Renderer to Main IPC (api.shell.respond) | Renderer issues the user's decision via api.shell.respond. Main NEVER decides; it routes to daemon.shell/respond. |
| Main to Daemon JSON-RPC | Main's sendToDaemon proxies the decision. The daemon's pendingApprovals Map holds the resolution Promise. |
| Main pendingApprovals mirror | Main keeps a mirror of pendingApprovals so it can resolve the bot name for always-allow persistence. This is metadata only - the canonical Promise lives in the daemon. |
| Renderer state store | The shell:request-approval notification arrives via broadcast(). The renderer subscribes once and dispatches to state/shells.ts. Authorization to render a modal is data-driven (the notification itself is the trigger). |
