# Plan 02-01 — Tracer slice: end-to-end `read_file` vertical slice

**As a** Localbot user,
**I want to** ask the bot to read a file from its workspace and see the contents render inline in the chat,
**so that** I can verify the full tool pipeline (LLM tool_use → daemon safe-path + audit → renderer block) works for one tool before the rest of the tool surface lands.

## Objective

Prove the Phase 2 architecture end-to-end with one vertical slice (`read_file`):

- **Daemon side** — allowlist-enforced `tools/list` + `tools/call`; safe-path resolution; stub bodies for `write_file`, `edit_file`, `list_dir`, `code_search` (those land in waves 2 and 3).
- **Main side** — Anthropic `tools` schema attached to `messages.stream`; per-turn agentic loop that detects `stop_reason: 'tool_use'`, dispatches via daemon, and forwards tool events to the renderer.
- **Renderer side** — `MessageBlock` discriminated union renders text + tool_use + tool_result blocks inline.

This is the **tracer** slice — every layer the phase touches gets exercised end-to-end on `read_file` before the rest of the tools expand outward. A real runnable `<verify>` at the end proves the architecture is sound; if any layer fails, we know within one task instead of after ten.

## Purpose

Phase 1 established the IPC + JSON-RPC + audit plumbing. Phase 2's risk is not the wiring (it's proven) but the **policy placement**: SEC-02 demands the allowlist lives in the daemon, not main; LLM-03 demands the loop resumes after tool_result; UI-03 demands the block surface is a discriminated union (back-compat with Phase 1's `content: string` JSONL). This plan proves all three policy placements with one tool before the surface multiplies to five.

## Output

- Working `read_file` tool end-to-end (LLM emits tool_use → daemon reads workspace file → result lands as inline `tool_result` block).
- Four stub tool files (`write_file`, `edit_file`, `list_dir`, `code_search`) that throw `not_implemented_yet` so `tools/list` already advertises the Phase 2 surface.

### C. Create `daemon/tools/safe_path.cjs`

Per RESEARCH.md §"Pattern 4". Exports `safePath(workspaceRoot, requested) → Promise<string>` and a private `err(code, message)` helper.

```javascript
// daemon/tools/safe_path.cjs
const path = require('node:path');
const fs = require('node:fs/promises');

async function safePath(workspaceRoot, requested) {
  if (typeof requested !== 'string' || requested.length === 0) {
    throw err('invalid_path', 'path is empty or not a string');
  }
  if (!workspaceRoot || typeof workspaceRoot !== 'string') {
    throw err('workspace_missing', 'workspace root not configured');
  }

  // Ensure workspace exists; resolve real path so symlinked roots are caught.
  await fs.mkdir(workspaceRoot, { recursive: true });
  const rootReal = await fs.realpath(workspaceRoot);

  const joined = path.isAbsolute(requested)
    ? path.resolve(requested)
    : path.resolve(workspaceRoot, requested);

  let resolvedReal;
  try {
    resolvedReal = await fs.realpath(joined);
  } catch {
    // File does not exist (write/edit of a new path). Fall back to parent realpath.
    const parent = path.dirname(joined);
    const parentReal = await fs.realpath(parent).catch(() => null);
    if (!parentReal) {
      throw err('outside_workspace', `parent does not exist: ${requested}`);
    }
    const insideParent = parentReal === rootReal || parentReal.startsWith(rootReal + path.sep);
    if (!insideParent) {
      throw err('outside_workspace', `path escapes workspace: ${requested}`);
    }
    return joined;
  }

  const inside = resolvedReal === rootReal || resolvedReal.startsWith(rootReal + path.sep);
  if (!inside) {
    throw err('outside_workspace', `path escapes workspace: ${requested}`);
  }
  return resolvedReal;
}

function err(code, message) {
  const e = new Error(message);
  e.code = code;
  return e;
}

module.exports = { safePath };
```

### D. Create `daemon/tools/read_file.cjs`

The ONE tool fully implemented in this plan. Reads UTF-8 string content from a safe path.

```javascript
// daemon/tools/read_file.cjs
const fs = require('node:fs/promises');
const { safePath } = require('./safe_path.cjs');

async function call({ path: requested }, ctx) {
  const resolved = await safePath(ctx.workspaceRoot, requested);
  try {
    const content = await fs.readFile(resolved, 'utf8');
    return { content };
  } catch (e) {
    if (e.code === 'ENOENT') {
      const err = new Error(`file not found: ${requested}`);
      err.code = 'enoent';
      throw err;
    }
    if (e.code === 'EACCES') {
      const err = new Error(`permission denied: ${requested}`);
      err.code = 'eacces';
      throw err;
    }
    throw e;
  }
}

module.exports = { call };
```

The `ctx` second argument (passed by registry) carries `workspaceRoot` + `toolCallId` + `signal`. See Task 1.E.

### C. Create `src/main/llm/loop.ts`

```typescript
// src/main/llm/loop.ts
import type Anthropic from '@anthropic-ai/sdk';
import { streamChat, type StreamChatResult } from './client';
import { callTool } from '../daemon/spawn';

export interface AgenticLoopOptions {
  messages: ChatMessage[];
  system: string;
  tools: Anthropic.Tool[];
  signal: AbortSignal;
  onToken: (delta: string) => void;
  onToolUse: (b: {id: string; name: string; input: unknown}) => void;
  onToolResult: (r: {toolUseId: string; content: string; isError: boolean}) => void;
  bot?: string;          // default 'default'
  maxTurns?: number;     // default 10
}

export async function runAgenticLoop(opts: AgenticLoopOptions): Promise<{
  text: string;
  toolCalls: Array<{id: string; name: string; input: unknown; output: string; isError: boolean}>;
  blocks: MessageBlock[];
}>
```

The loop:

1. Calls `streamChat({...})` once for the outer turn.
2. If `stopReason !== 'tool_use'`, appends text blocks to `blocks` and returns.
3. Otherwise iterates each `tool_use` block in `blocks`; for each:
   - Emit `opts.onToolUse({id, name, input})`.
   - Call `await callTool(name, input, {toolCallId: id, bot: opts.bot ?? 'default'})`.
   - On success: `opts.onToolResult({toolUseId: id, content: stringify(result.content), isError: false})`.
   - On error: `opts.onToolResult({toolUseId: id, content: 'Error: ' + err.message, isError: true})`. Do NOT route through `classifyError`.
   - Append a `tool_result` block to `messages` so the next LLM call sees it.
4. Re-call `streamChat` with the extended `messages`. Repeat until `stopReason !== 'tool_use'` or `maxTurns` reached.
5. If maxTurns reached with `stopReason === 'tool_use'`, surface as `EVENT_MESSAGE_ERROR {category: 'fatal', retryable: false}` (don't loop forever).

| renderer → IPC | Untrusted renderer process; cannot validate paths or tools |

| daemon → ripgrep (Wave 3) | Daemon spawns ripgrep as a child process; must kill on cancel |
